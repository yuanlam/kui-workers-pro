# 住宅代理与 Docker 接入

## 用户需要配置的 Secrets

在 Worker 的 **Settings → Variables and Secrets** 中设置：

```text
PROXY_USER=使用独立用户名
PROXY_PASS=使用独立强密码
```

缺少任一项时，住宅代理接口不会下发凭据。修改后需要重新部署 Worker。

集成版已内置住宅代理控制器，不需要设置 `PROXY_CTRL_URL`、`PROXY_CTRL_USER`、`PROXY_CTRL_PASS` 或 `PROXY_CTRL_TOKEN`。这些变量仅用于兼容独立的外部控制器。

## 节点选择与切换

住宅 IP 代理页面顶部为「节点总览」。桌面展示三列、平板两列、手机一列的节点卡片，每张卡片包含节点名称、在线/拨号中/离线状态、主出口与宿主机 IP、中文地区、已连时长、主备通道数量、并发连接、累计流量、端口、纯净度文字结论和实测延迟。点击卡片切换目标节点；当纳管节点不少于两台时，可点击「全部节点批量模式」进入或退出 `*` 目标。

「节点详情」保留目标 VPS、当前目标 VPS、主出口、备用出口四个等宽卡片。调度策略、出口地区、国家候选芯片和搜索提示统一显示中文地区名；表单仍提交标准协议值，中文地区名会在前端归一化为 2 位 ISO 国家码，`ANY` 仍表示全球自动。地区搜索同时匹配中文名与 ISO 代码。

候选评分与准入采用“纯净度优先、速度第二”的两阶段策略：

- **阶段一（候选预筛）**：拉取 VPN Gate 节点列表后，调用 `IPOK /api/batch` 对目标地区前 100 个候选执行批量风险预筛（6 小时缓存，失败冷却 5 分钟）。纯净度（纯住宅/低风险与风险标记惩罚）权重高于速度与延迟，优先把低风险纯住宅候选排在前面，同档纯净度再按速度与延迟择优。网页备用源也会读取可用的质量信息；未知会话数不会按零会话处理。
- **阶段二（拨号后出口核验）**：隧道连通后经该隧道依次查询 `IPPure /v1/info`（获取真实出口 IP、住宅/原生属性、`fraudScore` 与 ASN 组织）和 `IPOK /api/ip`（补充多源风险分与 `blocklisted`/`abuser`/`tor` 信号）。风险分达到高风险门槛（`fraudScore >= 56` 或 `ipokRisk >= 56`）、命中 `blocklisted`/`abuser`/`tor`，或非住宅机房出口（风险分 `>= 31` 或广播 IP）将被直接拦截并继续重试等待更低风险节点；两者均不可用时自动回退至 `api.ipify.org` 与 `testisp.info`。
- **主备晋升与赛马**：周期性更换健康备用通道时，候选评分须高出超过 25 分并通过入口连通性验证；备通道晋升主通道时优先保障纯净度（纯净度明显更优且速度达标时主动晋升，纯净度降级或未验证备通道禁止覆盖高纯净度主出口，纯净度相近时再按速度/延迟晋升）。

国家候选节点数量优先读取 VPN Gate 的 CSV 数据，接口不可用时读取其官方节点页面；若两者均不可用，面板保留最近一次成功的数量。没有可用缓存时，数量显示为“—”并提示读取失败。

服务器页面与住宅 IP 代理页面保留住宅/原生类型标签和风险数字上下文；住宅 IP 代理页在界面上优先展示 `IPPure` / `IPOK` 文字风险等级（如极低风险、低风险、中风险、高风险、待检测），原始风险分保留在提示 `title` 中。平台可用参考仍保留星级与可用标记，风险项明细仍保留命中数、洁净数与来源数字。

「出口 IP 详情」复用 `pc-ip-score-section`、`pc-ip-score-link` 与 `pc-native-score-container` 固定 DOM 契约，头部支持主出口/备用出口切换，并提供 `IPOK 详报 ↗` 外链。批量模式下该区块隐藏并清空，避免聚合数据伪装成单出口画像。

出口画像数据优先使用 VPS 心跳或实时通道上报的 `detail.ip_profile`，不产生额外面板公网查询。旧版 VPS 未上报该字段且存在有效出口 IP 时，前端回退调用 `GET /api/proxy/ip-profile/:ip`；响应中可包含 `ip_profile`、`ipok_risk`、`fraud_score`、`is_residential` 与 `is_native`。画像请求使用递增序列号，切换节点、切换主备或进入批量模式后，旧响应不会覆盖当前视图。面板会缓存最近五分钟的回退结果。

点击「重测纯净度」或「测延迟」调用 `POST /api/proxy/probe`，请求体为 `{ ip, action, role }`，`action` 只接受 `recheck_purity` 或 `probe_latency`，`role` 只接受 `active` 或 `standby`。按钮处于 loading 状态时不会重复提交。VPS 升级后会等待心跳直报；当前视图来自面板回退接口时可附带 `GET /api/proxy/ip-profile/:ip?refresh=1` 兜底刷新。旧版 testisp 深度质检卡片和 `diagView` 切换标签已移除。

局部代理的 AI 域名和 IP 规则使用 SukkaLab 在线规则集，sing-box 每日检查更新。更改 AI 规则来源后，需要更新 VPS Agent 并重新应用出口配置。

在住宅 IP 代理页的「目标 VPS」中选择一台服务器，「当前目标 VPS」会同步显示它的 IP、心跳、节点策略、主备通道、并发连接和累计流量；旧版 Agent 未上报实时指标时显示 `--`。主出口和备用出口分别展示中文地区、IP 类型、运营商、文字风险等级、IPOK 数据来源链接与实测延迟，可复制出口 IP，也可展开「通道详情」查看该出口的隧道、端口、首包延迟、吞吐和已连接时长。选择全部 VPS 时，两张出口卡分别统计主、备通道就绪的目标数。

点击备用出口卡片上的「切换至备用」后，新连接会使用新的出口，现有连接可能中断。如果目标地区已更改或备用隧道在切换前失效，VPS 会重新拨号。

需要重新选点时，使用「全量重拨」。这会断开现有隧道及其连接，再建立新隧道。测速结果反映 VPS 到测速目标的当前链路质量，不同目标网站和时间的实际速度可能不同。

## 监听范围

住宅 SOCKS 监听端口（默认 `7920`）由 `proxy-lite` 独占，默认仅监听 VPS 本机 `127.0.0.1`，供 KUI Agent 链式出口使用；`kui-agent` 不会在 `sing-box` 中创建同端口入站，避免端口冲突与自环。安装和升级脚本按「先就绪 `proxy-lite`，再启动 `kui-agent`」的顺序执行。除非确实需要从公网直连，否则不要开启公网监听。

`PROXY_PUBLIC_LISTENER` 是用户可调的普通变量。如需将新接入 VPS 默认设为公网监听，可设置：

```text
PROXY_PUBLIC_LISTENER=true
```

更推荐保持默认值 `false`，然后在管理员面板的 **公网监听** 页面按 VPS 单独开启。面板设置会覆盖该变量的默认值，并触发对应 VPS 的 proxy-lite 自动刷新监听范围。开启前应先轮换代理凭据，并通过防火墙或云安全组限制来源地址；面板会持续显示公网监听安全告警。

## Docker 容器接入

Docker 容器不需要开启公网监听。在面板的 **住宅 IP 代理** 页面填写该 VPS 的 Docker 网桥地址，通常为 `172.17.0.1`，然后下发策略。

该地址同时用于：

- `proxy-lite`：端口 `7920`
- Agent sing-box 检查入口：端口 `39482`

Compose 服务需要加入宿主机别名：

```yaml
services:
  your-service:
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

容器内使用：

```text
socks5h://代理用户名:代理密码@host.docker.internal:7920
```

`39482` 是本机无认证检查入口，不应暴露到公网。清空面板中的 Docker 网桥字段后，服务会恢复为仅监听 `127.0.0.1`。

## 排查建议

1. 确认面板显示 `residential_outbound.ready=true`。
2. 检查 VPS 实时日志中的主备通道和出口 IP。
3. 确认 `proxy-lite` 正常运行并独占面板配置的 SOCKS5 监听端口（如 `127.0.0.1:7920`），`sing-box` 配置中不存在同端口 `residential-socks5` 入站。
4. Docker 场景下确认网桥地址存在，且容器能解析 `host.docker.internal`。
5. 不要为解决容器访问问题直接开启公网监听。
